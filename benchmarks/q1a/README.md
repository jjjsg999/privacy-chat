# Q1A isolated diagnostic fixtures

No application imports, model calls, production sessions, credentials, scheduler or memory writes. Python standard library only. All commands run from the repository root with `.venv\Scripts\python.exe` (or another Python 3.12).

1. `python benchmarks/q1a/acquire.py --corpora` acquires the pinned, licensed text subset. This is the only network step. It verifies terms before downloading corpus content and fails closed on changed source hashes. AMI is retrieved as original NXT XML members through bounded ZIP byte ranges, with original license and documentation, not a JSON mirror. No media is downloaded. A future upstream change needs a deliberate new fixture revision, never silent reselection.
2. `python benchmarks/q1a/normalize.py` regenerates 30 fixed fixture IDs, references and manifest offline. `fictional_facts.json` is the preauthored answer key; the renderer seals all eight keys before writing dialogue. Never include that file in test prompts.
3. The two small offline checks are `python benchmarks/q1a/check.py sources` and `python benchmarks/q1a/check.py leakage`. They were each run once for Q1A.1. Results are in ignored `outputs/`.

`manifest.json` and `sources.lock.json` contain metadata and content checksums. Corpus text, normalized input copies, held-out reference copies and outputs are ignored in Git. Preserve attribution/license files with local fixtures, and do not redistribute MeetingBank adaptations under a less restrictive license. LoCoMo and MeetingBank are restricted to noncommercial use here. The local license snapshots and root dataset report provide source URLs and attribution.

Only a case's `raw_input_file` is eligible as model input. The manifest, references, source corpora (which contain labels), lock, this README and fictional facts are evaluator-only. They are separated by directory, not encrypted. No evaluator/runner has been implemented or authorized in this stage. Holdout references must stay closed during later development. Correct answers occurring naturally in transcripts are source evidence, not leaked packaging.

Fixed split: AMI ES2005/ES2006 families, QMSum Bed016, MeetingBank row 2, LoCoMo conv-43/conv-44 and fictional_07/08 are holdout. The other cases are development. AMI project families and LoCoMo conversations do not cross the split. No selected QMSum source overlaps AMI cases (selected QMSum meetings are ICSI Bed meetings). Source-group separation does not imply separation of every human speaker across an entire public corpus.

AMI controls ES2004c/ES2005d have no human-annotated action sentences. They are annotation-empty controls, not exhaustive negatives. QMSum/MeetingBank references measure salience, and LoCoMo measures bounded memory QA; they cannot be pooled with AMI/fictional action accuracy. Full AMI/QMSum inputs can be lengthy; token estimates include serialized turn metadata and are heuristic, not tokenizer measurements. LoCoMo windows contain three complete sessions with original timestamps and speakers; reference evidence is not highlighted.

## Q1A.2 — Codex-run offline harness

Codex runs `.venv\Scripts\python.exe benchmarks/q1a/harness.py` from the repository root. No user execution is needed. The default selects **development only**, uses empty mock responses and writes `outputs/report_development_A.json` plus a reference-free `outputs/review_development_A.json`. This is plumbing validation, not model quality. Holdout is untouched in Q1A.2. Codex runs the three targeted tests with `.venv\Scripts\python.exe benchmarks/q1a/test_harness.py`; do not invoke broad product-test discovery.

The harness uses actual `meeting_extraction.extract_meeting`, validation, `memory_store`, reconciliation, `role_context.current_background` and `adviser.retrieve`. `sandbox.py` executes the original source files under injected module dependencies; it does not duplicate production extraction or reconciliation. A rejecting HTTP dependency and a replaced `engine.complete` make this standard-library harness independent of HTTP packages. Every case gets fresh temporary storage under ignored `outputs/worker_*`; temporary memory is removed on exit. The audit guard is enabled before loading production modules and rejects repository data/settings/credential reads, writes outside that temporary directory, reference/corpus reads during execution, sockets and subprocesses. No app, scheduler or transport startup modules are imported. Source-module bindings and bytecode settings are restored on exit; guards are process-local, so run this entry point only in its own worker process.

Mock completions run synchronously through the production coroutine without an event loop, so even loop-internal sockets are unnecessary; a coroutine yielding actual I/O is rejected. Production `engine.private_messages`, `PrivacyEngine.tokenize` and extraction rehydration still run. The mock analyzer deliberately reports no findings: this tests token-map plumbing and configured fictional identity terms, **not Presidio PII detection quality**. There is no live-provider switch. Later authorized real calls would require the real analyzer, unchanged production privacy/budget boundaries and separate authorization; this harness cannot activate them.

For a later offline response replay, Codex may pass `--responses outputs/<file>.json --arm B`. The JSON maps case IDs to ordered raw JSON response strings or candidate objects, one per meeting. Missing responses reject that meeting; they never fall back to a provider. `--arm` accepts an opaque alphanumeric label. No old/new comparison is executed now. The report retains case/source IDs, input/reference and production-component/prompt fingerprints, response/request hashes, chronology, candidate output and evidence offsets for later pairing. Separate review packets contain candidate artifacts and input fingerprints but no gold references, scores or model identities. A later paired run must keep case inputs and scoring versions fixed and conceal the arm mapping from reviewers.

### Adapters and report fields

| Area | Measured offline | Explicit limits |
|---|---|---|
| JSON/contract | JSON parse validity, production contract acceptance and failures, per-response denominators | Valid JSON can still violate the production contract. |
| Grounding | Verbatim quotes plus owner/date/project/name/subject substring anchors | Anchor validity is not entailment; hallucination/factual support stays `not measured` with uncertainty. Rejected masked drafts may fail anchors because restoration never succeeded. |
| AMI actions | Predicted/reference counts, missing fields, description word counts and evidence offsets | Semantic matching, false-positive rate, specificity quality and owner/date accuracy are `not measured`; no official precision/recall. Empty human action sections are nonexhaustive controls. |
| Fictional actions | Grounded exact scripted task coverage; exact proposal-as-action flag; owner/date accuracy only for grounded exact task matches; unknown-field abstention | Exact matches are mechanical proxies; unmatched paraphrases need review. Missingness is separate from accuracy. Confirmed aliases may count for evaluator attribution; production exact-name matching remains unchanged. |
| Insights | Reference-unit denominator, plus fictional literal state/risk/decision coverage proxy | Human summary coverage, executive usefulness and semantic factual support require a judge; references are not exhaustive fact inventories. Current production extraction does not emit QMSum answers or narrative summaries. |
| Longitudinal fictional | Timezone-aware chronological replay, processed source IDs, final state projected from actual adviser retrieval, verified role preservation and source links | This is register projection, not generated QA. Empty mock output correctly has no recovered state. Exact-name role gate applies; confirmed speaker aliases are not automatically mapped by production. |
| LoCoMo | Input session IDs/timestamps retained for adapter diagnostics | `adapter not supported`: no episodic dialogue-to-memory/QA path exists. Zero extraction/retrieval/answer attempts; excluded from success/failure accuracy denominators. |
| Usage | Request count, request/response SHA256 and chars/4 token estimates; actual offline cost $0 | Model usage, future live cost and semantic scores are `not measured`; no pricing or network lookup. |

Each metric has its own numerator, denominator and status; no overall score is computed. Zero-denominator ratios are undefined, never 100%. Action, insight and longitudinal case sets overlap for fictional cases, so lane counts must not be summed into a new case denominator. `lane_denominators` lists eligible and unsupported cases separately. The structural and anchor results describe **mock or saved responses**, never the current model. AMI decisions are available for later semantic review; suggested-follow-up classification is `adapter not supported` because the current schema cannot distinguish proposals and commitments.

Execution consumes only normalized inputs. Gold reference reads occur only after the production execution context has ended, and no callback receives the reference object. Fictional verified core is seeded as manual baseline only in temporary memory; extraction itself receives exactly the production transcript-only contract, so the harness does not silently add role context or repair alias behavior. Temporary IDs and clocks are deterministic; production source and transcript hashes remain intact.

The three tests cover (1) masked source-only mock extraction, chronological state replacement, canonical-role gating and supported owner/date proxies; (2) rejected anchors/malformed JSON plus a structurally valid, semantically wrong state that makes an explicit positive assertion fail; (3) denied production/reference access, writes, credentials, sockets and live/missing-response fallback. They do not establish natural-language extraction quality.

`paid_guard.py` is an unactivated future admission seam, not a live runner or CLI. Neither `harness.py` nor `readiness.py` instantiates it. The readiness code imports only its pure arithmetic planning function. No Q1A prompt authorizes paid dispatch. A later separately authorized worker must use real production privacy and completion, durable benchmark-only budgets, exact plan/model authorization, current verified all-charge prices and per-request persistent development reservations, including repairs and graders. The dormant dispatch path has not been exercised; its offline refusal/restart/concurrency checks are prerequisites before later use. No ordinary production call is reclassified as development by this seam.
